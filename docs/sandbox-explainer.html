What this is

Anthropic's sandbox-runtime (srt) wraps any Linux process in bubblewrap: a private mount namespace where only listed paths are writable, no network namespace at all so every connection must go through srt's own proxies and their domain allowlist, and a seccomp filter that refuses new user namespaces and Unix sockets. Claude Code uses it on laptops for its Bash sandbox. This project runs it on the cluster.

kind: workspace

Claude Code in the cluster

The pod runs srt -- claude remote-control. Sessions are started and driven from claude.ai/code or the Claude app; the pod opens outbound connections and listens on nothing.

kind: managed-agents-worker

Managed Agents worker

The pod runs srt -- ant beta:worker poll. Claude Managed Agents sessions queue tool calls; the worker claims them and executes bash and file tools inside the sandbox.

delivery

One chart, GitOps

Published as an OCI chart; the app-of-apps entry pins a chart version and an image tag. No node changes were needed: kernel 6.8, k3s 1.36 and containerd 2.3 already support pod user namespaces.

The one idea that made it work

bubblewrap needs to mount a fresh /proc, and a normal pod's masked /proc forbids that. Upstream's answer is a weaker mode. The cluster's answer is hostUsers: false (a pod user namespace, GA in Kubernetes 1.36) plus procMount: Unmasked: root inside the pod becomes an unprivileged host uid, which is exactly the condition under which Kubernetes allows an unmasked /proc. Full-strength srt then runs as uid 1000 inside an unprivileged pod. The spike on the real node proved it.

  1. 1
    You send a messageThe Claude app or claude.ai/code sends it to Anthropic's Remote Control relay. The pod opened that connection outbound when the server started; nothing on your network accepts connections.
  2. 2
    The server inside the pod receives itclaude remote-control is running as uid 1000 inside srt. The model answers with a Bash tool call. In default permission mode the app asks you to approve it; bypassPermissions is disabled by managed settings and cannot be turned on.
  3. 3
    The command runs inside bubblewrapClaude Code spawns the shell. Because the whole server is already wrapped, the shell inherits srt's namespaces: it sees only the read-only root, the writable /workspace, /home/agent and /tmp, a fresh /proc with a handful of pids, and no network interface except loopback.
  4. 4
    npm asks the proxyHTTPS_PROXY points at a Unix socket bridged by socat into srt's HTTP proxy outside bubblewrap. The proxy checks registry.npmjs.org against the allowlist: listed, so it resolves the name, checks the address is not loopback, link-local, RFC 1918 or the node's own, and dials out.
  5. 5
    The CNI checks againThe pod's egress policy only allows DNS to the cluster resolvers and TCP/443 to the same FQDN list. The DNS proxy saw the lookup, the destination matches, the packet leaves. Had the name been example.com, srt would have answered 403 and the CNI would never have seen a flow.
  6. 6
    Output returnsstdout goes back through Claude Code to the relay and to your phone. srt records any denial it made for the debug log; with debug.srt on, it is in Loki.

The three gaps an enterprise port must close

kernel

A separate kernel per sandbox

One bare-metal node, no nested virtualisation. The chart accepts isolation.runtimeClassName for gVisor or Kata; adding one is a hardware change, not a chart change.

credentials

Credentials never inside the sandbox

The wrapped process can read its own login and the GitHub token. Enterprise: srt credential masking behind TLS termination, GitHub App tokens, Workload Identity Federation.

audit

Signed, centralised audit

Loki has stdout; transcripts sit on a volume. Enterprise: OpenTelemetry from Claude Code, structured srt and Hubble denials, append-only storage with retention policy.
