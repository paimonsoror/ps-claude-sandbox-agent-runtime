Controls

Where the build stands against published controls

Sixty-odd controls from OWASP (LLM Top 10, Agentic Threats and Mitigations, Securing Agentic Applications), Anthropic's own sandboxing and Managed Agents guidance, NIST SP 800-190 and AI 600-1, the CSA red-teaming guide, Kubernetes Pod Security Standards and the agent-sandbox threat model, MITRE ATLAS, and the security models of Codex, Docker Sandboxes, E2B and Daytona. Every row has a status and a porting note; the full matrix is docs/controls-matrix.md.

The three gaps

What an enterprise port must close first

kernel

A separate kernel per sandbox

Sources: OWASP SAAG 3.2.3a and 9.2a, agent-sandbox threat model, Docker Sandboxes, E2B. Here: one bare-metal node, no nested virtualisation; the defence is user namespace + bubblewrap + seccomp on a shared kernel.

Port: a sandboxed RuntimeClass (gVisor or Kata/microVM) through isolation.runtimeClassName with srt in weak mode inside; this also restores PSS restricted.

credentials

Credentials never inside the sandbox

Sources: Anthropic cloud sessions' credential proxy, Docker and Daytona secret placeholders, OWASP SAAG 3.2.8. Here: the wrapped process can read its own login and the GitHub token; the environment key is queue-scoped.

Port: srt's credentials masking behind tlsTerminate with an enterprise CA, or an external credential proxy; GitHub App tokens per session; Workload Identity Federation.

audit

Signed, centralised audit

Sources: OWASP ASI T08 and SAAG 9.4, ATLAS M0024, Claude Code OpenTelemetry guidance. Here: stdout in Loki, transcripts on a volume, srt denials only with debug on.

Port: OTLP from Claude Code to the collector, structured srt and Hubble denials, append-only storage with retention and redaction policy.
