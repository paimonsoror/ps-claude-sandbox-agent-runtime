Architecture · design baseline 2026-10-26

One image, three boundaries, no inbound port.

Claude agents execute inside the homelab cluster: Claude Code itself, driven from a phone over Remote Control, and an Anthropic Managed Agents worker. Each runs under Anthropic's sandbox-runtime at full strength, inside a pod that is unprivileged on the host because of a user namespace, behind a network policy that allows the same short list of names the sandbox proxy allows. Delivered by ArgoCD from one chart, one file per sandbox.

The problem

An agent that can run commands needs a place to run them.

A laptop is the wrong place

Claude Code's Bash sandbox protects the laptop, but MCP servers, hooks and file tools still run on it, and the laptop has to stay open. Unattended work wants a machine that is nobody's daily driver.

A container is not a sandbox

Root in an ordinary pod is root on the node. The runtime masks /proc, which stops bubblewrap from mounting its own; upstream's answer is a weaker mode that exposes the container's process table.

Egress is the exfiltration path

Anything the agent reads can leave through any host it can reach. The sandbox proxy filters by name; nothing outside bubblewrap was filtered at all until the CNI policy was written from the same list.

It has to be measurable

"Secure" is not a property a chart can claim. The build is measured against OWASP, NIST, Anthropic's own guidance, Pod Security Standards and MITRE ATLAS, with every gap named.

The decision, in one paragraph

Opinionated on purpose

ADR-0003

User namespace, unmasked /proc

hostUsers: false makes pod root an unprivileged host uid, which is exactly the condition under which Kubernetes allows procMount: Unmasked. Full-strength bubblewrap follows. Proven on the node.

Evidence →
ADR-0005

One bubblewrap layer, around everything

srt wraps the whole process, so MCP servers and hooks are inside the boundary too. Stacking Claude Code's inner Bash sandbox would require allowing nested user namespaces, which weakens the outer denies.

Layers →
ADR-0006

One list, two enforcement points

The same domain list renders srt's proxy allowlist and a Cilium policy with toFQDNs on 443 plus DNS. Private ranges are refused even for allowed names. No ingress exists.

Egress →
ADR-0007 · 0009

Remote Control, no ingress

The workspace is driven from claude.ai/code or the Claude app over a connection the pod opens outbound. The login lives on a volume; a token from setup-token cannot do Remote Control, so it is not used.

Runbook →
ADR-0016

One file per sandbox

Definitions are a map with per-kind defaults, so a sandbox is five lines and any number of files merge. An ApplicationSet turns a directory of them into one Application each.

Fleet layout →
ADR-0013 · 0015

Gaps named, path drawn

Three gaps an enterprise must close: a kernel per sandbox, credentials that never enter the sandbox, signed audit. The north star adds a control plane and microVM substrates on top of this same image.

Two kinds of sandbox

Same image, same pod contract, different command

kind: workspace

Claude Code in the cluster

The pod runs srt -- claude remote-control in server mode: up to eight sessions, each in its own git worktree, created on demand from the phone. The workspace volume is a clone of a repository; the home volume holds the login and the sessions.

Needs: a one-time claude auth login and a one-time confirmation over kubectl attach.

kind: managed-agents-worker

Managed Agents worker

The pod runs srt -- ant beta:worker poll. It long-polls one environment's work queue with an environment key scoped to that queue, executes the bash and file tools inside the sandbox, and posts results back. The org API key never exists in the cluster.

Needs: a Secret with the environment id and key, created outside git.
